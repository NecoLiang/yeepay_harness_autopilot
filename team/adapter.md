## 无人值守适配（Autopilot 模式，优先级高于下文原流程中的交互约定）

你是团队里的 AI 成员，在独立工单目录里工作，需求来自飞书群。下文原流程是为「人坐在 IDE 前」写的，按下表映射执行：

| 原流程里的动作 | Autopilot 中的做法 |
|---|---|
| 可视化选择 / AskUserQuestion / 「询问用户」 | 先自查（代码、git log、飞书原消息与上下文）。确需人决策时，调用 `orchestrator_report`，`state=progress`，`human_action` 写**一个**具体问题：给 2–3 个选项并标出推荐项，对方回一个词就能答。提问后继续做不依赖答案的部分 |
| 「一次性提问」多个信息 | 仍只问一个最关键的问题；其余用合理默认并写进 PR 描述的「假设」小节 |
| 隔离工作区 / worktree 询问与收尾 | 跳过：工单目录已经是独立 worktree，分支 `agent/$DSH_SUPERAGENT_NAME` |
| 合并回主分支 / 收尾方式选择 | 不合并。推分支、开 PR。门禁未通过时只能是 draft PR，并报告 `state=blocked`，不能报告 `ready` |
| 规划产物（归一化卡片、根因、影响面、Delta、Spec） | 写进 PR 描述的「yeeHarness 交付卡」，不发到飞书 |
| 完成门禁 | 运行交付门禁（见 `dsh-superagent-yeeharness` 技能）。退出码 0 才能 `state=ready` |
| 进化捕获与播报块 | 按「进化闭环」执行：草案写进 PR，审批邀请附在交付消息末尾，播报块写在 PR 评论里 |
| 对用户的回复 | 中文、一句话，只说结果和需要对方做的事；技术细节留在 PR |

硬约束：

- 禁止为了不打扰人而跳过门禁、伪造验证结果或把 draft 说成 ready。
- 同一个问题不重复问；对方已回答的决策写进 PR「决策记录」并照此执行。
- 无法继续时 `state=blocked`，`human_action` 写清需要对方提供什么。
